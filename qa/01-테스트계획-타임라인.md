# 테스트 계획 — 예방치료 타임라인

| 항목 | 내용 |
|---|---|
| 대상 | 우리 가족 덴탈 관리 앱, 예방치료 타임라인 기능 |
| 대상 버전 | `main` 브랜치 (2026-11-25 기준) |
| 작성일 | 2026-11-25 |
| 기준 문서 | `README.md` 주요 기능, `PLAN.md` 3장(연령별 기준)·7장(일정 계산) |

## 1. 목적

구성원의 생년월일로 만들어지는 예방치료·검진 일정이 **올바른 날짜에, 올바른 대상에게, 올바른 상태로** 표시되고 알림까지 이어지는지 확인한다.

## 2. 범위

| 포함 | 근거 |
|---|---|
| 아이 일정 8종의 권장일 계산 (생후 12·18·30·42·54·72·144개월) | 날짜 계산 오류는 잘못된 치료 시기 안내로 이어진다 |
| 아이/어른 구분 (만 19세), 스케일링·국가건강검진 일정 | 구간이 바뀌는 경계에서 결함이 생기기 쉽다 |
| 상태 칩 (완료·오늘·예정 D-N·이후·지남) | 사용자가 가장 먼저 보는 정보 |
| 알림 예약 (7일 전, 당일) | 놓치면 기능의 목적이 사라진다 |
| 일정의 수명 주기 (등록·완료 체크·수정·삭제) | 저장된 데이터가 구성원 정보와 어긋날 수 있다 |

| 제외 | 이유 |
|---|---|
| 검진 기록, 치아 차트, 양치 기록, 백업/복원, AI 상담 | 별도 기능. 각각 따로 계획한다 |
| 실제 기기의 알림 수신 (OS 권한, 절전 모드) | 실기기가 필요하다. 이번에는 예약 목록 계산까지만 본다 |
| 성능, 접근성 | 이번 범위 밖 |

## 3. 접근 방법

| 수준 | 방법 | 대상 케이스 |
|---|---|---|
| 로직 | `flutter test qa/timeline_cases_test.dart` 로 자동 실행 | A~E 그룹 28건 |
| 화면 | 앱을 실행해 손으로 확인 | M 그룹 10건 |

사용한 설계 기법: 경계값 분석(날짜, 나이, D-60), 동등 분할(아이/어른/국가검진 대상), 결정 테이블(알림), 상태 전이(일정 수명 주기).

## 4. 환경

| 구분 | 내용 |
|---|---|
| 로직 테스트 | macOS, Flutter 3.44.1, 메모리 SQLite |
| 화면 테스트 | iOS 시뮬레이터 또는 `flutter run -d chrome` |
| 테스트 데이터 | 기준일 2026-11-25. 생년월일은 케이스마다 명시 |

## 5. 시작·종료 기준

- 시작: 앱이 빌드되고 기존 단위 테스트가 통과한다.
- 종료: 모든 케이스를 한 번씩 실행했고, 실패한 케이스마다 버그 리포트가 있다.

## 6. 리스크

| 리스크 | 대응 |
|---|---|
| 상태 칩이 기기의 현재 시각을 직접 읽어 날짜를 고정할 수 없다 | 오늘 기준 상대 날짜(±N일)로 케이스를 만든다 |
| "등록 3년 뒤" 같은 시간 경과는 그대로 재현할 수 없다 | 저장된 항목과 코드 경로를 확인해 판단하고, 리포트에 그 사실을 적는다 |
| 일부 기대 결과는 기획 문서에 없다 (큰 아이의 지난 항목 처리 등) | 기대 결과에 "기획 확인 필요"로 표시한다 |
